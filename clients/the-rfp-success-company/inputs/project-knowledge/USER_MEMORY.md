## Information Gain Standards

Every page must pass these tests before publishing:

### Delta Test
"If this page disappeared from the internet, would anyone lose access to something they couldn't find elsewhere?" If no, the page needs more substance.

### Deferral Rule
If the page can't reach HIGH information gain, defer publication until it can. Don't ship MEDIUM or LOW.

### HIGH / MEDIUM / LOW Assessment
- **HIGH** — 5+ client-specific information gain elements (named clients, quantified outcomes, named engagements, specific operational detail, direct client quotes, methodology application)
- **MEDIUM** — 3 elements with at least 1 client-specific
- **LOW** — Generic, AI-synthesizable from public web content

### Information Gain Sources (RFP Success-Specific)
1. Evaluator-side expertise (Lisa, Susan, Anna)
2. Proprietary methodology (4x4 Framework™, D.A.R.E. Method)
3. Specific client outcomes with named companies and metrics
4. Real sales call patterns and prospect questions
5. Industry-specific evaluator behavior across 30+ verticals
6. State-specific procurement rules and rhythms
7. Composite storytelling with irrelevant detail principle

## Entity SEO + GEO Operating Principles

- **Primary Entity Visibility rule:** Topic must be identifiable from the header alone; JSON-LD `about` must match the header
- **Keyword placement:** Primary keyword and brand name required in the **first sentence** (not just first paragraph)
- **Two-layer content architecture** — visible body copy + extractable answer capsules with `.answer-capsule` CSS class
- **Fan-out query mapping** — every page targets a primary query + 5–10 related semantic variations
- **Triple schema stacking** — WebPage + (primary entity schema) + FAQPage on every conversion page
- **Speakable schema** on hero quotes, outcome stat blocks, answer capsules
- **llms.txt** at root, updated when new pages publish
