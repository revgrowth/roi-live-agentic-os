# Design Template Brief
## Service Cluster Page
### Blue Tree Landscaping
**Prepared by:** Jason Spencer | [ROI.LIVE](http://ROI.LIVE)
**For:** Creative Design Team **Date:** February 2026 **Reference:** All 55 cluster pages across 5 pillars (e.g., `/landscapes/garden-design/`, `/hardscapes/paver-patios/`, `/pools/inground-pools/`)
* * *
## What This Template Is
The Service Cluster Page is the **workhorse template of the entire site.** There are **55 of these pages** — the highest page count of any template type. Every cluster page lives beneath one of the 5 service pillar pages and goes deep on a single specific service.
Where the pillar page answers "Who does landscaping in Southeastern PA?", the cluster page answers "Who installs drip irrigation in Southeastern PA?" or "Who builds paver patios in Blue Bell?" It's a narrower, more specific, more transactional page.
**The cluster page is closer to the bottom of the funnel than the pillar page.** Visitors arriving here have already done some research. They know what they want. The job of this page is to confirm they've found the right company and get them to request a consultation — faster and more directly than the pillar page does.
* * *
## How It Differs From the Pillar Page
This is the critical distinction for the design team. The cluster page uses the **same design system** — same fonts, same colors, same component library — but it is **assembled differently.** Fewer sections, shorter content, earlier and more aggressive conversion flow.

| Element | Pillar Page | Cluster Page |
| ---| ---| --- |
| Page length | 3,000–4,000 words | 1,200–1,800 words |
| Number of sections | 16 | 9–10 |
| Hero | Full viewport, immersive | Full viewport, same treatment |
| Owner personal promise | ✅ Yes | ❌ No |
| Planning questions grid | ✅ Yes | ❌ No |
| Services grid (links DOWN) | ✅ Yes — links to clusters | ❌ Replaced by Related Services (links LATERAL + UP) |
| Integration section (5 cross-pillar cards) | ✅ Yes | ❌ No — replaced by 2–3 related service callouts |
| Process steps | 5 steps, full detail | 3 steps, abbreviated |
| Testimonials | 3 full testimonials | 1–2 testimonials |
| FAQ | 8–10 questions | 4–6 questions |
| Video testimonials section | ✅ Yes | Optional — include if video exists for this specific service |
| First CTA appearance | After hero trust bar | After hero trust bar AND again after core service description (earlier) |
| Breadcrumb | `Home > [Pillar]` | `Home > [Pillar] > [Cluster Service]` |

* * *
## Page Personality
**Length:** Focused. 1,200–1,800 words. Every section earns its place. If a section doesn't directly help the visitor decide to hire Blue Tree for this specific service, it doesn't belong on this page.
**Tone:** More direct, more transactional than the pillar page — but still warm and authoritative. The visitor is further along in their decision. Speak to that.
**Scroll behavior:** The page should convert before the visitor reaches the bottom. A motivated visitor should be able to read the hero, skim the core service description, see one proof point, and hit the CTA — without needing to read the whole page. The full page is there for the thorough researcher. The CTA is there for everyone else.
* * *
## Section-by-Section Layout Specification
* * *
### 1\. HERO SECTION
**Purpose:** Establish specific service authority immediately. The visitor should know within 2 seconds that they've found the right page.
**Layout:** Identical component to the pillar page hero. Full-viewport height, full-bleed photography, dark gradient overlay, content left-aligned on desktop.
**Content stack:**
1. Breadcrumb — now 3 levels deep: `Home > Landscapes > Garden Design & Planting`
2. Pre-headline trust badge — service-specific (e.g., "Degreed Designers. Locally Sourced Plants. 1-Year Warranty.")
3. H1 — specific to this service and location (e.g., "Garden Design & Planting in Southeastern Pennsylvania")
4. Subheadline — 1–2 sentences, specific to this service's core value proposition
5. Primary CTA button + Secondary CTA
6. Trust bar — same 4-signal format as pillar page
**Design notes:**
*   Same hero component as the pillar page. No redesign needed — just different content and a service-specific hero photo.
*   The H1 is more specific here. "Garden Design & Planting" not "Landscape Design & Installation."
*   Hero photography should show this specific service — a garden bed installation, not a generic landscape.
* * *
### 2\. CORE SERVICE DESCRIPTION SECTION
**Purpose:** This section does not exist on the pillar page. It's unique to cluster pages and is the most important section on the template.
This is where the page explains exactly what this service is, what Blue Tree does, why it matters, and what makes Blue Tree the right choice — all focused on this one specific service.
**Layout:**
*   Two-column on desktop: primary content column (left, ~60% width) + supporting sidebar (right, ~40% width)
*   Single column on mobile — sidebar content stacks below the main copy
**Primary content column:**
*   Section headline (H2) — service-specific, benefit-driven
*   Body copy: 3–4 paragraphs covering what the service is, how Blue Tree approaches it, what makes their approach different, and what the outcome looks like for the homeowner
*   Inline text links to related cluster pages where contextually relevant (e.g., the drip irrigation page mentions sprinkler systems — link to `/landscapes/sprinkler-systems/`)
**Supporting sidebar (sticky on scroll, desktop only):**
*   "Ready to get started?" mini CTA card: short headline + 2-sentence pitch + CTA button + phone number [@Jason Spencer](#user_mention#132116866) we really want prospects to fill in a form rather than call the office. The phone number should be at the bottom of the fill a form page. Check: [https://keystonecustomdecks.com/schedule-an-estimate/](https://keystonecustomdecks.com/schedule-an-estimate/)where the phone number is at the bottom. Unlike Keystone, like our current website, we want to ask (buttons) a few more questions (services interested in, budget (opt.) and timeframe (opt))
*   Key service details block: 3–5 bullet points of fast facts (e.g., "1-Year Plant Warranty," "Locally Sourced Materials," "Free On-Site Consultation," "Serving Southeastern PA Since 1983")
*   Trust signals: NALP badge, Licensed & Insured badge, Google rating
**Design notes:**
*   The sticky sidebar CTA is a cluster page feature that does NOT appear on the pillar page. It's the most important CRO addition in this template. A visitor who decides mid-copy that they want to call should never have to scroll to find a CTA.
*   The sidebar should feel like a helpful summary panel, not an intrusive ad. Clean card treatment, not a banner.
*   On mobile, the sidebar content (CTA card + key details) should appear immediately below the hero, before the body copy — not buried at the bottom.
* * *
### 3\. PROCESS SECTION (ABBREVIATED)
**Purpose:** Show that hiring Blue Tree for this specific service is simple and clear.
**Layout:**
*   Section headline
*   Three steps only — not five. On a cluster page, the process is abbreviated because the visitor already has category awareness from the pillar page (or doesn't need it).
*   Steps displayed horizontally on desktop with connecting visual, vertically on mobile
*   Each step: number → headline → 1–2 sentence description
*   No post-installation callout box (that lives on the pillar page)
**Three universal cluster page steps:**
1. Free Consultation → We visit your property and assess the specific scope
2. Custom Plan & Proposal → Tailored approach + transparent pricing for this service
3. Professional Installation → Expert crew, clean site, done right
**Design notes:**
*   Same step component as the pillar page, just 3 instances instead of 5.
*   This section should be compact — it's confirmation, not education. The visitor doesn't need a deep dive into process at this point.
* * *
### 4\. PROOF / PORTFOLIO SECTION
**Purpose:** Show real examples of this specific service.
**Layout:**
*   Section headline (e.g., "Garden Design Projects Across Southeastern PA")
*   2–4 project thumbnails — filtered specifically to this service category
*   Each thumbnail: project photo → hover overlay with project type + location
*   CTA below ("View Full Portfolio →" linking to `/portfolio/?tag=landscapes`)
**Design notes:**
*   Fewer photos here than on the pillar page — quality over quantity. 2 exceptional photos beat 6 mediocre ones.
*   If project photography for this specific service isn't available at launch, omit this section rather than showing unrelated work.
*   No masonry layout here — uniform grid (2-column on desktop, 2-column on mobile) is cleaner at this scale.
* * *
### 5\. TESTIMONIALS SECTION
**Purpose:** Social proof specific to this service.
**Layout:**
*   1–2 testimonials maximum — not 3
*   If 2 testimonials: side-by-side cards on desktop, stacked on mobile
*   If 1 testimonial: full-width card, centered, with a larger quote treatment
*   Each card: decorative quotation mark → quote text → client name + location
*   CTA below ("Read More Reviews →" linking to `/reviews/?tag=[pillar]`)
**Design notes:**
*   Same quote card component as the pillar page — just fewer instances.
*   Prioritize testimonials that mention this specific service by name if they exist. Generic testimonials are better than nothing but service-specific quotes are significantly more powerful here.
* * *
### 6\. RELATED SERVICES SECTION
**Purpose:** This replaces the "Services Grid" from the pillar page. Instead of linking DOWN to cluster pages, it links LATERALLY to sibling cluster pages and UP to the parent pillar.
**Layout:**
*   Section headline: "Explore More Landscaping Services" (or relevant pillar name)
*   3–4 compact service cards in a horizontal row on desktop, 2-column grid on mobile
*   Each card: service name → one sentence → link
*   One card should always be the parent pillar page ("All Landscape Services →" linking to `/landscapes/`)
**Design notes:**
*   These cards are intentionally lighter and smaller than the Services Grid cards on the pillar page. They are navigation aids, not feature presentations.
*   Simple card treatment: clean border, service name bold, one-line description, text link. No large icons, no photography.
*   This section should feel like a helpful "you might also be interested in" — not a competing services page.
*   The parent pillar link (back UP to `/landscapes/`) should be visually distinct — perhaps styled as a secondary button or with a different card treatment — so it reads as "go back to the full picture."
* * *
### 7\. LOCAL EXPERTISE / SERVICE AREA SECTION
**Purpose:** Confirm geographic relevance and provide location-specific entry points.
**Layout:**
*   Compact version of the pillar page's Service Area section
*   Section headline + 1 short paragraph of local context
*   County list (inline text)
*   2–3 featured town links relevant to this service (e.g., for garden design: Blue Bell, Gwynedd Valley, Wayne)
*   Small map visual (same component as pillar page, just smaller)
*   CTA ("Find Your Area →")
**Design notes:**
*   This section should be roughly half the visual footprint of the pillar page's service area section.
*   The map can be a smaller, cropped version of the same map component — no need for a new component.
*   Town links here are editorial choices — pick the 2–3 towns most relevant to the audience for this specific service.
* * *
### 8\. FAQ SECTION
**Purpose:** Answer the most common questions about this specific service. Target AEO.
**Layout:**
*   Section headline
*   4–6 FAQ items — accordion style, same component as pillar page
*   All items collapsed by default
*   CTA below ("Have More Questions? Contact Us →")
**Design notes:**
*   Same accordion component as the pillar page — just fewer items.
*   FAQs here should be specific to this service, not general landscaping questions. Those live on the pillar page.
*   Inline links within FAQ answers are encouraged — link to related cluster pages where relevant.
*   FAQPage schema required on all items.
* * *
### 9\. FINAL CTA SECTION
**Purpose:** Last conversion opportunity. Same purpose and visual treatment as the pillar page.
**Layout:** Identical to the pillar page Final CTA section. Full-width, visually distinct background, large headline, primary CTA button, secondary phone CTA, trust reinforcement strip.
**Design notes:**
*   Use the exact same Final CTA component as the pillar page. No changes needed. This is consistent across both templates and across all 60 service pages (5 pillar + 55 cluster).
* * *
## What's NOT On This Page
To be explicit for the design team — these sections from the pillar page are intentionally absent from the cluster template:
*   ❌ Personal Promise section (owner letter) — pillar page only
*   ❌ Planning Questions grid — pillar page only
*   ❌ Design Approach 3-column feature blocks — pillar page only
*   ❌ Integration section with 5 cross-pillar service cards — replaced by the leaner Related Services section
*   ❌ Video testimonials section — optional on cluster pages only if service-specific video exists
*   ❌ "Why Blue Tree" 6-block value section — pillar page only. Trust is established on the cluster page through the sidebar CTA card, testimonials, and FAQ — not a dedicated why-us section.
* * *
## Sticky Elements
**Sticky Header:** Same as pillar page — appears after hero scrolls out of view. No changes.
**Mobile Fixed CTA:** Same as pillar page — tap-to-call or "Request Consultation" fixed to bottom of viewport.
**Desktop Sticky Sidebar:** The CTA card in the Core Service Description section should be sticky on scroll (desktop only) — it follows the visitor as they read the main copy column, ensuring the CTA is always visible. This is the key CRO addition unique to cluster pages.
* * *
## Responsive Behavior Summary

| Section | Desktop | Tablet | Mobile |
| ---| ---| ---| --- |
| Hero | Full viewport, left-aligned | Full viewport, centered | 80vh, centered |
| Core Service Description | 2-column (60/40) | 2-column (60/40) | 1-column, sidebar below hero |
| Process Steps | 3-step horizontal | 3-step horizontal | 3-step vertical |
| Portfolio | 2–4 column uniform grid | 2-column grid | 2-column grid |
| Testimonials | 2-column or 1 full-width | Stacked | Stacked |
| Related Services | 4-column row | 2x2 grid | 2x2 grid |
| Service Area | Map + text side-by-side | Stacked | Stacked |
| FAQ | Full-width accordion | Full-width accordion | Full-width accordion |
| Final CTA | Full-width | Full-width | Full-width |

* * *
## Performance Requirements
Same as pillar page:
*   All images lazy-loaded below the fold
*   Hero image optimized and preloaded
*   LCP target: under 2.5 seconds
*   Sticky sidebar should not cause layout shift on scroll
* * *
## Schema & SEO Notes for Developers
*   BreadcrumbList schema: 3 levels — `Home > [Pillar] > [Cluster Service]`
*   Service schema with LocalBusiness nested provider (same structure as pillar page, scoped to this specific service)
*   FAQPage schema on all accordion items
*   All outbound links (Related Services, pillar link) must be crawlable anchor tags
*   Canonical tag: self-referencing
*   OG image: hero photography cropped to 1200x630
* * *
## The One-Sentence Brief for Your Design Team
